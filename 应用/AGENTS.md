# AI 与自动化贡献入口

本目录是独立发布工程。先读 `README.md`、`docs/AI-CONTEXT.md`、`CONTRIBUTING.md`；按修改范围再读 `docs/ARCHITECTURE.md`、`docs/FEATURES.md`、`docs/VALIDATION.md`。无需研究工程、维护者记忆服务或个人备份即可运行公开测试。

- 最终交付目标是可双击打开的桌面应用；当前有 SwiftUI 模拟／真实 USB 模式、内置环境 macOS 包与物理 CLI；维护者已于 2026-10-21 确认 dev25 安装包实机验收完成，当前扩大样本测试；不据此宣称所有机身或长期稳定性已验证。界面复用核心服务，不能复制一套补丁或 USB 事务逻辑。
- 桌面首屏名为“操作前须知”，包含自动启动自检、范围、验证进度、风险及免责声明；不要用“打开应用”命名阶段。阅读确认由服务端管理，只用于导航，不是合同接受或设备写入授权；风险文案统一维护在 `notice.py`。
- dev14 起按功能选择解锁／关闭，支持“全选缺失”；未选中功能保持不变，选择集为空时拒绝写入。dev15 将电子快门声音并入正式清单，声音可独立选择，sound-after-exposure 仅为历史验证基线。稀疏功能状态备份／恢复只覆盖固定功能扇区与结构守卫；整盘／分区／固件镜像备份与恢复仍未实现，不为了改框架而开发或验证整盘模块，也不得把稀疏备份称为整机备份。
- 配置向导 `preparation.py` 不访问设备。人工确认不等于固件兼容；每次设备操作仍做新的只读预检。取消或环境失败时不能构造设备后端。
- dev34 解锁／关闭后停留独立结果页，断电步骤和检查路径统一维护在 `desktop/aftercare.py`。写入／回读成功不等于机身功能验收成功；无需修改不称已写入。物理事务完成先退出 USB 服务并释放锁，退出异常单独提示；模拟和物理都必须重新准备并 inspect 才可继续，不能自动 home 或沿用旧兼容结论。
- 桌面暂时隐藏备份与恢复入口，直到完整备份恢复实现并验证后再设计展示；不添加“更多”入口或占位按钮。保留稀疏备份恢复核心、开发者命令、测试及用户文件；隐藏不等于已提供自动备份或历史撤销。
- dev25 按用户要求暂禁用位移多帧合成与动态增强防抖；界面、选择、离线规划、恢复、请求与原生写入掩码均须遵循 `available`。保留历史字段识别与完整守卫，不自动撤销已有实验状态。dev23 曾将动态增强防抖纳入第六项功能：只拥有最终 App 2＋WBI 4 字节，不纳入旧列扩展或强制清零未知计数；关闭前先把相机录像防抖切回增强／标准。细节见 `docs/动态增强防抖.md`。
- 功能定义在清单，不能在界面、向导或连接器中硬编码新偏移。设备范围或字节掩码变化需要更新适配、重建原生载荷及相应证据。
- 公开源码禁止重新引入已排除的三份历史原厂扇区数组；`scripts/build_source.py` 有路径及已知块哈希守卫，不能以改名绕过。`verified/` 与上游参考代码保留来源及许可证。修复运行代码时不要顺手改写历史归档或其哈希。
- 个人学习定位和声明见 `docs/声明与使用边界.md`。USB root 教程、功能修改及应用的公开计划保留；如实说明执行／写入行为，不能以“学习”“不强制入侵”宣称自动免责或删去已分发二进制的对应源码。声明不为 GPL 另加用途限制。
- 功能选择、统一 profile v2、灵活曝光和电子快门声音的修改范围与证据记录在 `docs/FEATURE-SELECTION.md`；未知字段、守卫、未管理字节或功能依赖不因“全选”而放行。
- 默认验证命令为 `python3 scripts/check.py --strict`；它排除原生仿真，不访问 USB。安装 test 依赖且模拟器可工作时再运行 `--native --strict`。明确报告跳过与失败，不能将模拟或 dry-run 写成实机写入验证。
- 自动化测试使用合成数据、模拟端点和临时目录；不要访问真实相机或维护者状态目录。真实写入测试需要维护者明确授权，CI 不执行硬件操作。
- 不自动重发写入器、增加强制放行参数或扩大可写设备范围。不把窗口前镜像称为完整备份，不混用明文块设备和 Pico 密文镜像。
- 不提交固件、个人备份、校准数据、密钥、ProductInfo 原文或带个人路径的本机报告。
- 修改需附有范围、原因、对应测试和仍待验证事项；只针对当前改动做必要验证，不为纯文案增加镜像测试。

## 文件存放与收尾

- 关闭前FTP实机只读组件：`data/native/close-state.elf`及对应源码／清单，使用`scripts/build_close_state.py --output <新路径>`独立重建。无任意地址或setter；通过原生代码守卫、运行/保存双读、两个传输通道及空读请求队列确认后才允许现有FTP关闭。常驻资源管理器不等于介质占用；未知资源状态仍拒绝。dev4新增独立`close-setting.elf`固定原生设置载荷及四项读取；使用同一构建脚本加`--setting`重建。其开启态实机验收仍进行中，不能将离线测试称为已完成自动停用验收。
- 桌面代码在 `desktop/macos/` 与 `desktop/windows/`，测试与构建脚本复用现有入口，不向工程根输出 `main` 或独立备份副本。临时编译用系统临时目录；验证报告在主工程 `output/运行/`，独立克隆时可用被忽略的 `reports/主题/任务/`。
- 不再新建 `.local-validation/`；历史报告已按原路径归档，参见主工程目录规范。归档资料不属于独立运行依赖。
- `dist/` 一个发行版本一个目录，应用与对应源码、校验文件成组保存；过期版本移入 `dist/历史版本/`，不覆盖已分发文件。任务结束清理可再生构建缓存、同步现有文档及引用。

## Windows 本地预览

- 当前Windows候选为0.4.1 x64，对齐Mac 0.4.1的FL23修复与直接更新、四项关闭前设置恢复和两阶段结果页；未纳入FTP增量更新。Windows实机验收与用户审核仍待完成，不把Mac机身记录写成Windows通过。
- Windows设备锁使用`msvcrt`等价实现，继续与新版`guard_pending_settings`在同一持锁范围内协作；不能恢复仅支持POSIX的提前拒绝，也不能绕过待重启设置守卫。
- Windows连接占用只提示在原工具正常结束任务，不调用POSIX强制接管。`host_io.py`的CREATE_NEW、write-through、UTF-8及DLL适配保持，关键记录保存失败必须先于写入器停止。
- Windows无编译器验证机使用`tests/test_fl23_package.py --export-native-fixture`生成的合成材料；三组文件事务均须执行实际ARM64仿真，材料绑定当前生成器、测试及源码摘要，不替换正式载荷。

- 自动驱动准备仅由`windows_driver.py`的专用提权助手执行，限定Sony 0E76／047D／0336；主应用与固件事务不得提权。已绑定WinUSB直接跳过，0E76与0336共用同一助手，精确的0336 INF先预注册到驱动库，驱动变化后刷新libusb。PVE使用usb0物理端口和usb2=054c:0336双槽，避免单槽旧描述符。libwdi二进制和源码必须匹配`desktop/runtime-dependencies.json`及`desktop/windows/driver/README.md`，不得替换为未审查安装器。

## 结构设计约束（2026-11-07已确认）

应用开发先读[跨平台与插件化方案](docs/跨平台与插件化方案.md)，遵守第0节和第4.1节。共用核心与平台适配分层，能力包绑定修改、准备与验收流程；核心负责设备锁、身份／守卫、事务和独立回读。不得各平台复制功能分支或只更新JSON放宽原生写入器。FL23等待、重启和菜单检查由流程定义与证据驱动，不以计时完成代替功能验收；同次操作固定包和流程版本。框架替换为后续预研，当前不得为架构迁移改动已有验证载荷。结构变化先更新原设计和迁移说明，不能另立平行实现。设计约定不代表已实现，也不替代设备／发布授权。

涉及在线服务时先读[轻量服务端设计](docs/轻量服务端设计.md)：独立自愿实例统计、私有脱敏反馈和静态签名更新分层；不得把下载量当安装人数、把统计与更新捆绑、在Worker放发布私钥或开放日志公开读取。专项设计尚未实施，云资源与GitHub发布沿用既有审核流程。

## 共用核心同步（2026-11-08）

`release/` 是核心唯一来源。修改共享模块后执行 `python3 scripts/sync_windows_core.py`，核对 `shared-core-manifest.json`；不要手工复制或独立修改已同步文件。Windows 仅保留 `desktop/windows/`、`windows_driver.py`、USB 后端、权限助手、资源加载及打包差异。每次同步后运行 `python3 scripts/check.py --strict` 和 Windows UI 烟测；真实 WinUSB 与功能写入仍需独立实机验收。
