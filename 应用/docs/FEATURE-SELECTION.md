## FL23修复包原包更新（0.4.1）

旧版FL23通过已知包的完整长度／SHA识别，功能保持“已解锁”，另显示“可更新”；独立更新按钮只选择FL23，忽略其他勾选。选择“未解锁或可更新”也包含旧版FL23，可与其他功能依次执行。当前修复版为no-op；未知或残缺安装不按旧版本放行。

## 统一 profile v2

### 可选功能修订（FTP 更新候选，未开放界面）

清单可为功能声明 `revision` 和从修订 2 起连续排列的 `updates`，每项更新通过 `edit_ids` 引用该功能自己的增量字段。原有基础字段必须保留，禁止重复引用、跨功能引用或没有有效基础字段的修订定义。当前运行清单尚未启用这项元数据，原六项识别行为不变。

`feature_updates.revision_status` 将基础能力与更新程度分开：完整旧版保持 `state=enabled`，另返回 `installed_revision`、`target_revision`、`update_state=available`；更新完成为 `current`，已知部分更新为 `incomplete`。未解锁、基础不完整或未知状态不被当作可直接升级的旧版。

`plan_update` 复用普通解锁规划，但再次核对改动只属于本次待补字段。`operations._execute_session` 的 `update` 操作仅接受一个明确功能，取得新鲜扇区后才规划；写前日志、原生比较、回退和独立回读仍走同一事务。通信失联保留不确定结果，不自动重发。桌面／CLI 更新入口在实机验收后接入，不能以界面之前的检查替代锁内新鲜预检。

旧 profile 用“整扇区规范化哈希”判断兼容性。FTP／快门帘与灵活曝光恰好落在同一批 App 扇区，且字段不重叠，但整扇区哈希会把另一个功能的修改当成不匹配。

v2 改为：

- 每个目标扇区记录 `unmanaged_sha256`：把该扇区所有已知字段字节置零后计算哈希；
- 字段值由清单逐项校验，允许同扇区不同功能分别处于已知状态；
- 每个扇区由 `edit_ids` 生成识别掩码，保持历史状态及未管理字节校验；写入掩码额外排除 `available=false` 的功能，主机请求与原生写入器都拒绝这些字节；
- 守卫扇区继续使用完整 `sha256`。

统一窗口为 **260 个扇区**：149 个目标扇区、111 个结构守卫。它覆盖 FTP、快门帘、灵活曝光、电子快门声音（含 `/dev/nflasha8` CP 触发）、位移多帧合成和动态增强防抖的全部字段。

## 选择模式

- `--feature ftp --feature exposure`：显式选择；
- `--all-missing` / 桌面“全选缺失”：只补齐本版开放且当前未解锁的功能；
- 桌面“全选”：选择本版全部开放功能；
- 桌面“清除”：空选择，解锁／关闭／恢复按钮禁用。

“全选”不是强制放行：未知字段、守卫变化、未管理字节变化仍会阻止整个操作。功能可以声明 `requires`，但当前开放功能之间没有字段依赖；电子快门声音与灵活曝光字段无重叠，可以只选声音。`sound-after-exposure` 只是验证基线，不是运行时前置。

## 桌面流程

1. 连接相机、完成准备、只读检查。
2. 主页显示每个功能的当前状态和勾选框。
3. 选择功能，或点“全选缺失”。
4. 点“解锁所选功能”或“关闭所选功能”。
5. 结果页显示本次事务与回读状态；未选中功能不应发生变化。

备份仍保存完整统一窗口；恢复只写回当前勾选的功能字段。因此可以用同一份备份只恢复 FTP，而保留灵活曝光的当前状态。

## 命令行

```sh
a6700-unlock device inspect
a6700-unlock device unlock --feature ftp --feature exposure
a6700-unlock device unlock --all-missing
a6700-unlock device close --feature exposure
a6700-unlock device restore --feature ftp
```

`--all-missing` 仅用于 `unlock`，不能与 `--feature` 同时使用。恢复时省略 `--feature` 表示恢复本版全部开放功能。

## 边界

- 只读预检与写入仍使用同一固定 260 扇区窗口，没有任意地址或整盘 API。
- 功能选择不改变原生写入器的掩码检查、写前校验、失败回退或独立回读。
- 不同功能共享扇区时，掩码取并集；写入前仍逐字节检查未管理内容。
- 跨适配版本的新旧备份会被拒绝，不会按新偏移猜测恢复。
- 2026-10-20 已完成实机只读预检、声音 close dry-run、声音关闭→独立回读→重新解锁→回读；关机重开后的声音菜单与实际播放仍需用户确认，其他功能未执行写入。

### 已实现的共用流程

固定读取器双读29项模型字段和四个保存开关，FTP另核对两传输通道及读请求队列。派生内部状态只修改current，影子槽不是保存值，不能要求两者相等；真正的设置仍必须运行／保存一致。所有字段仍须通过两遍稳定读取、合法枚举及原生代码指纹检查。

- `close_preparation.py` 集中维护四项规则，要求运行值、保存值和相机空闲状态均已确认；FTP还需传输、连接及介质释放状态，曝光还需退出存储调用。每次状态请求绑定新nonce，拒绝过期回复和非布尔的确认值。
- 全组选项都可处理后才调用设置适配器。每个设置动作先记录意图，调用一次，再独立读取目标和其他所选项；无回读、保存不同步、其他选项被意外改变或通信失联都停止。适配器负责原生正常停止、有界等待和保存，不能把Backup写入包装成原生停止。
- 设置发生变化后重新读取固件目标及守卫，再次核对机身状态，禁止使用调整前的扇区前态。普通关闭、无固件增量的关闭、备份恢复到关闭状态均走该检查。
- 混合关闭先预检普通功能及FL23安装器，任何一项不通过都不调整设置或写入固件。后续各安装器仍重新检查，不复用预检结果放行。FL23已关闭时也核对原有外观／存储引用，不能以no-op跳过。
- 结果分别记录 `settings_write_attempted` 和固件 `write_attempted`，并列出设置的计划／完成范围。`settings-prepared`表示仅恢复设置、固件无需修改；准备失败／取消／不确定各有结果状态，不自动重新开启FTP。模拟模式另用`simulated_settings_write_attempted`，真实写入标志保持false。
- Mac按钮改为“检查并关闭”，允许选择已经关闭的功能检查残留设置；结果页显示每项准备结果。演示场景“关闭前：相关功能正在使用”走真实控制器和规划器，但不连接相机。

USB后端的`read_close_state`和`reset_close_setting`分别使用独立载荷：读取器没有设置动作，复位器只接受四项固定的开启到安全状态转换。复位走原生模型API及通知流程，不直接写Backup；调用只发送一次，随后最多15秒、30轮独立读取确认运行、保存及资源释放。设置意图先持久记录；未闭合意图阻止客户端新设备会话，维护者供电入口也检查同一记录。两份载荷均可用`scripts/build_close_state.py`（复位器加`--setting`）从配套源码独立重建。

目标是将本次关闭的功能恢复到**原厂支持、可以安全卸载的状态**。已有合法设置保持；只修正依赖待移除功能的值，不重置整个相机或清空功能配置。

### 灵活曝光的退出细则

退出目标明确为菜单中的“P/A/S/M模式”；恢复后由相机原有模式控制选择P、A、S或M，不统一改成某个曝光档位。关机快门帘的退出目标仍为“关”。电子快门声音的新增选项按上述用户修订恢复为“开”，不沿用前版设计的“关”。

- 先核对录像／拍摄忙碌、当前模式、曝光控制类型及对应保存值。即使当前在照片模式、独立自动／手动菜单不可用，也不能据此认定已保存的灵活曝光设置已退出。
- 使用原生控制类型切换及其通知／保存流程，确认切回P/A/S/M后再修改固件。不能仅改Backup保存值或清空三个独立自动／手动开关来模拟退出。
- 已有原生菜单回调离线结果显示，返回P/A/S/M后主类型回到原值，三个独立开关的当前状态变为“不可用”，影子偏好及自定义键在受测模型中保留；“不可用”是该模式下的正常派生状态，不应强制写成全自动或全手动。此结果没有执行真实存储提交。
- 2026-10-19用户曾确认切回P/A/S/M后正常关机、再次进入灵活曝光也正常；同时观察到主动类型往返后，原混合自动／手动组合变为全手动。因此自动卸载不能承诺切换过程完全不改变曝光状态，也不能把这条手动验收当作应用自动设置接口已验证。
- 正在录像时暂停，提示先停止录像。处于1／2／3存储调用或机身拒绝切换时，提示退出存储调用，按机身要求切到视频及P/A/S/M拨盘位置后重新检查；不通过清除限制或伪造拨盘状态放行。
- 需专项验证视频／S&Q切换及存储调用后是否会重新带回该控制类型；尚未证明独立存储的配置不自动覆盖，也不清空全部存储档。若发现相关残留且无法可靠处理，则阻止关闭并提示用户修正。
- 写前摘要明确显示“曝光控制类型：灵活曝光模式 → P/A/S/M模式；自动／手动状态可能随相机切换而调整”。记录并核对实际联动变化，超出已验证范围时停止后续固件修改。

### 共用执行顺序

1. 根据当前读取的安装状态和用户选择生成计划。界面在执行按钮上方列出将自动调整的项目，例如“停止FTP；音频信号改为开；关机时快门改为关；曝光控制类型改为P/A/S/M”，一次“停用并关闭”操作覆盖这份明确计划。
2. 取得共享设备锁并核对前序任务，重新读取**所有选中项**的设置、运行状态和内容守卫。任一项未知／不可安全处理时，在任何固件写入前停止。不能沿用页面加载时的状态或以菜单已隐藏推断运行功能已停用。
3. 通过已验收的原生接口逐项停止运行、恢复合法值、保存并独立回读。FTP还需运行停止与资源释放证据；固件参数目录ID不等于Backup键，持久值读回也不等于后台工作线程已退出。
4. 所有项目通过后，按当前内容重新生成固件修改计划。设置保存可能影响同扇区或WBI前态，不能继续使用停用前的旧候选。重新执行既有身份／布局／非目标字节检查，再撤回固件修改、独立回读及退出服务。
5. 结果分别报告“运行功能已停用”“固件修改已撤回”“待重启／机身验收”。需要重启或更换协议时明确进入相应阶段，重新连接后必须再次读取；不伪造后台完成或自动沿用旧兼容结果。

共用检查必须覆盖普通关闭、FL23／中文组合、混选及恢复备份中导致功能关闭的路径。混选在处理第一项前完成全组选项预检，避免先撤回FTP或声音、再因FL23槽引用异常而停止。菜单已经隐藏或固件已为关闭状态的旧异常机身，也不能因no-op分支跳过必要的运行状态检查。

### 失败与验收要求

- 停用／保存／回读不明确时不发送固件写入器；有在途传输时采用正常停止／等待，不强杀、不清队列、不以超时当作空闲。需要用户在机身操作时给出对应路径，处理后重新检查。
- 设置已调整而固件修改尚未成功时，如实记录已改变的设置和仍保留的功能。默认保持已停止的功能，不自动重新开启FTP，也不把固件回退等同于设置回退。传输响应不确定时不自动重发。
- 日志只记录白名单设置的前后值、阶段、来源及回读结论；不读取或写入FTP凭据到报告。设置写入与固件写入分别记账，不能因没有改固件就称未修改相机。
- 接入自动执行前，逐功能验证读取语义、合法枚举、正常停用、持久化及重启保持；覆盖已安全状态、正在运行、新增选项、未知状态、超时、取消、保存后失联、混选前置失败，以及未选功能和合法设置保持。模拟通过不能替代真实停止传输／资源释放的验收。

dev4已实现真实原生设置调用和独立回读。FTP实机出现“开关已关闭并保存、真实IO已停止，但网络退出仍在等待”的场景：保留全部固件功能，明确提示重启后继续；重连只读复核已返回的调用，不重发关闭命令。只有正常返回收据、服务恢复和独立IO空闲证据齐全时才允许此重启；实际传输、回读未知或原生调用结果未知仍阻断。逐项及全组同机身验收和最终冷重启复核已通过，详见VALIDATION.md；在途FTP上传及跨机身兼容性不在已通过范围内。
