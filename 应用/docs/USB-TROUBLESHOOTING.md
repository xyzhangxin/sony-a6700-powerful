# USB 连接排查

先运行 `a6700-unlock doctor`。它只检查本机环境和包内资源，不表示相机连接或实机适配已经通过。

## 其他工具占用连接

桌面 dev5 在锁冲突页显示可唯一定位的占用进程，提供带确认的“强制接管”。先检查其他软件没有拍摄、传输或写固件任务；接管会结束该进程，随后需重新准备并连接，不自动续写。无法唯一定位、非本用户进程或已知仍有设备任务时不提供强制结束。普通用户无需调试台，未被持有的旧锁文件不妨碍连接；不要手动删除锁文件。完整行为见[应用流程](PRODUCT-FLOW.md#连接占用与强制接管dev5)。第三方软件不使用本机共享锁时，不保证能由此定位其 USB 独占。

## 准备连接

仅当已有且开启 FTP 时，停止传输、关闭 FTP 并重启；没有 FTP 菜单可直接继续。接线前选择 MSC（海量存储器）并关闭自动关机，保持唤醒，仅连接一台目标相机。具体菜单路径见 [相机准备图解](CAMERA-PREPARATION.md)。终端运行 `a6700-unlock device inspect`，先验收目标读取，再安排功能写入。

`inspect` 不发送功能写入器；它仍需认证、上传临时配置与读取 ELF，在相机进程中执行读取代码。临时目录不是纯 RAM 保证，不能描述为相机上完全零写入。

## macOS 接管与管理员密码

普通 MSC 导照片由 macOS 存储驱动处理；本工具的固件访问还需要临时接管 USB 并进入相机维护服务。当前实现弹出的 Mac 管理员授权不是相机 MSC 的连接密码；当前环境可能要求输入密码，不能据此承诺所有系统都提供 Touch ID。授权后 MSC 提示可能消失、相机可能回到拍摄或菜单页面；以应用实际操作结果为准，不因这一现象自行拔插，也不忽略真正的会话中断或回读错误。接口接管要求参见 [Apple deviceCapture 文档](https://developer.apple.com/documentation/iousbhost/iousbhostobjectinitoptions/devicecapture)。

dev33 起按 Sony 已知 MSC 身份或 MSC 接口描述符发现相机，不先打开 bulk 端点，不要求插有存储卡、存在磁盘卷或存储驱动。已知 MSC 身份在描述符暂不可读时仍保留为候选；实际端点、协议及固件内容在后续检查，不把“找到 MSC”当作适配完成。多台 MSC 相机仍需只保留一台。

默认连接流程只有一次接管和协议必需的两阶段认证，不先恢复驱动、重置 USB 或重复扫描卸载外部磁盘。失败后显示阶段，由用户重新连接，不自动重发整个流程。已安装的本机 helper 若与本版内置组件完全相同，可继续用已有授权；旧 helper 不覆盖新版行为，也不自动改系统 helper 或 sudoers，可能重新出现一次系统授权提示。

内置环境桌面版使用包内已校验的预编译组件，通过系统管理员授权；不需要接收者安装编译器或系统 libusb。源码 CLI 的接管助手在临时目录编译，需要 Command Line Tools、系统 libusb 和终端 sudo 授权。两者都只接管所选相机，不再先扫描卸载存储卷。连接前先关闭访问相机的其他应用。

非交互环境无法提示密码时会立即返回 sudo 错误。在自己的终端运行 `sh start.sh device inspect`，或双击启动工具后选择对应操作。密码直接交给系统 sudo 提示，不写入工具配置或报告。

`--no-capture` 只用于本次连接中接口已被手动接管的情况；它不能绕过系统驱动锁。重新插拔后通常需要再次接管。项目不自动安装永久 root 助手或修改 sudoers。

启动检查只加载 libusb 和检查所需函数，不初始化 USB 上下文。上下文在接管完成后才创建，并在 MSC→服务身份切换后刷新；macOS 接管会改变设备注册状态，提前初始化或长期复用旧枚举上下文可能导致旧进程找不到 MSC，而新进程能找到。若系统仍能看到相机但应用报找不到 bulk 端点，保留阶段信息，先排查进程和接管顺序，不扩大匹配范围或绕过兼容性检查。

dev35 修复了上下文刷新／重连时提前释放的错误：不能直接对 PyUSB 拥有的上下文调用 `libusb_exit`，旧 Device／ResourceManager 可能仍持有引用，且 PyUSB 的终结器还会再次释放。刷新只替换缓存引用，让旧上下文在所有关联对象释放后由 PyUSB 收尾。回归测试使用固定 PyUSB 版本的真实对象及终结器、合成 C 函数，不访问设备，覆盖刷新时不提前释放和最终恰好释放一次。API 约束参见 [libusb 生命周期文档](https://libusb.sourceforge.io/api-1.0/group__libusb__lib.html)。

dev36 进一步固定底层原生对象的释放顺序：PyUSB 1.2.1 的 `_Device`／`_DevIterator` 本身不持有 backend，即使未手动 exit，销毁过程中也可能先释放 context 再 unref device。适配层让原生对象持有 owner，完成底层 unref/free-list 后才允许上下文销毁；枚举和父设备路径均有离线回归。19:00 的本机崩溃发生在该释放阶段，先前一次连接通过不能排除这个收尾缺陷。

授权接管后进入服务模式时，MSC 存储连接会改变；若此时本地服务崩溃，拔插数据线并不会重启死亡的进程。dev35 会显示“本地设备服务已停止”，可主动重新启动服务、回到准备流程；这个入口只检查环境，不接管、认证、读写或自动重放之前的请求。若中断发生在解锁／关闭／恢复期间，结果按待核实处理，先保留记录并核实机身状态，不能把重新启动本地服务当作完成回滚。

授权用于取得维护接口控制权，与普通 MSC 文件访问不同。切换后相机可能不再显示 MSC，而回到拍摄或菜单页面；请保持连接，以应用检查、写入和独立回读的结果判断，不必因画面变化重新插拔。

0.2 修复 USB 上下文／原生设备释放顺序：本地设备、迭代器及父设备包装对象持有所属上下文，先释放设备引用，再释放上下文；刷新缓存不手动提前调用 `libusb_exit`。本机服务中断页可重新启动服务，但不自动接管相机或重放写入。

## 认证超时／退出失败

进度依次显示寻找 MSC、第一次认证、等待服务身份、第二次认证、服务响应确认。报告中的阶段用于定位，不记录原始 ProductInfo。

`dev3` 已修复多组 bulk 端点选择导致第二次认证超时的问题。请先确认运行新版本。若设备进入服务模式后仍超时、或提示退出未获确认，先保留 `result.json`，拔掉 USB、关机重开，再按 MSC 模式连接。不能把仍显示 Sony USB Device 的服务身份当作正常 MSC，连续盲试也不会修复接口状态。STOP 的管道错误可能来自身份切换；工具会独立枚举，只有观察到唯一 MSC 才记录 `msc-observed`，否则提示人工处理。

尚未发送写入器时报告 `write_attempted=false`；只读预检失败不能推断功能已修改。写入请求发送后丢失结果则是 `uncertain`，应先核实当前状态，工具不会自动重发。

操作明确完成后按结果页关机、断开 USB／其他外接供电、拔出电池、至少等待 10 秒、插入电池再开机检查。不要在写入或回读期间执行。

## 首次检查报 `04000010`（Issue #18）

Issue #18 的日志在 `inspect` 阶段返回 `04000010`（相机状态 `0x10000004`），记录为 `write_attempted=false`。专项排查定位到相机临时文件服务的挂载准备：首次使用时挂载目录可能尚未建立。专项测试包会在每个已认证会话首次暂存文件前初始化挂载，失败则停止后续文件传输。 [Issue #18](https://github.com/xyzhangxin/sony-a6700-powerful/issues/18)

2026-11-13，维护者确认另一位遇到同样报错的 Mac 用户已通过实机验收，实际构建号待核对。已向 Issue #18 的 Windows 反馈者发出 0.4.2.dev2 专项测试邮件，Windows 实机结果待回复。 [Windows 专项包校验记录](../../output/运行/应用/Windows042-04000010测试版/package-check.json)

0.4.3 的共用 USB 源码已包含这项准备步骤。2026-11-13 本地 USB 和 FL23 服务专项回归 37 项通过。发版验收须核对 Mac／Windows 成品都带上该修复，并在首次使用的机身上确认连接检查通过。回归覆盖同一会话复用、重连后重新准备，以及准备失败时停止载荷传输。

## 操作互斥

桌面已认证会话从接管前到退出始终持锁；保持连接期间其他工具需要等待，使用结束后退出相机模式或关闭应用释放会话。CLI 每次操作沿用同一共享锁。设备锁位于本机用户状态目录的 `sony-a6700-ftp/.assistant.lock`，与研究向导共用。更换 `--state-dir` 不绕过设备锁；锁文件保留，通过文件句柄持锁，不能靠删除锁文件解除忙状态。

## 内容或布局不匹配

预检结果会区分固件结构、功能区内容、未知功能状态与功能依赖。0.5.0 诊断候选在主反馈中保留系统构建号、连接阶段及耗时、错误码、前 16 个失败校验项及是否尝试写入、是否回读和是否退出。脱敏附件和离线导出提供适配摘要及完整校验分类。报告不附原始固件数据、实际内容哈希、相机序列号或本机路径。

2026-11-19 核对 0.4.3 反馈，能读到的同类 Windows 附件均报告守卫 `0/67/90/133`。守卫 0 对应已知 ext2 主超级块。0.5.0 对已知基线的检查点区分魔数不匹配、仅运行字段变化和其他字段也变化。守卫 67／90／133 可标记是否精确匹配已有 SonyCameraTool FTP 变体。发布候选的这些诊断分类不改变固件校验结果。收到新增报告后，再按实际分类选择验证过的恢复路径。

macOS 环境会记录弹窗授权和 MSC 接口接管步骤。原生接管组件明确提示未找到唯一相机时归入设备查找失败。仅有通用授权错误时仍需结合阶段事件判断。FL2／FL3 在机身里重启的反馈需使用意见反馈里的机内诊断采集，重点核对已安装载体修订和 AP／CP 异常记录。

2026-11-12 的 0.4.2.dev1 定制包精确识别 SonyCameraTool 1.0.0 在 App 守卫 67、90、133 的已知修改，并保留第三方字节。2026-11-13 用户反馈该包可以解锁，但通用版仍拒绝，回放自定义键只有一个 FTP 选项。兼容识别只解决定制版进入功能管理，不能完成向通用版迁移。

为此新增独立的 [FTP 一次性迁移修复](FTP-MIGRATION.md)：用另行绑定并重建原生载荷的适配集，精确撤回六处已知修改的 7 个差异字节，补齐已有实机写入／回读证据的 134 字节自定义键矩阵；FTP 基础缺项按通用定义补齐，其他功能保留。全部矩阵字段均在通用 0.4.2 检查窗口之外。写前必须证明目标能通过通用版原始规则，写后独立回读并另存 `public-042-inspection.json`；显式禁用第三方兼容放行。未知内容和未闭合写入仍阻断。反馈机身重启、两个菜单选项及通用版实际连接须分别验收。

`blocked` 表示完整字段、扇区或布局守卫不符合已知适配。没有强制写入开关。先保留报告并核对机型、固件、历史修改；本次窗口前镜像也不是全盘备份。当前仅适配已知 A6700 2.00 布局，实时 WBI 差异仍需实机排查。

公开反馈可提供错误阶段与脱敏后的 `result.json`。先移除本机路径等个人信息；不要上传 `preimages.json`、`targets.json`、原始 ProductInfo 或整机备份。
