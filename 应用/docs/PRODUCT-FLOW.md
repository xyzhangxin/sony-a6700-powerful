# 桌面应用流程与交互约定

最终交付是内置运行环境的 macOS 桌面应用。dev19 交互改版使用三步状态条：**操作前须知 → 准备并连接 → 功能管理**。默认相机模式启动仅做本机检查，可切换演示使用合成数据；相机模式复用真实 USB 服务与事务逻辑。环境检查、人工声明、固件预检分别呈现。

## 三步主流程

| 阶段 | 页面与用户动作 | 服务端约束 |
|---|---|---|
| 操作前须知 | 机型范围、设备／数据风险、保修及免责声明直接可见；本机检查自动运行，组件详情和验证范围按需展开。阅读确认后“开始准备相机” | 本机检查未通过、未阅读或服务未就绪时不能继续；阅读确认不是写入授权或合同接受 |
| 准备并连接 | 一页展示 FTP 条件处理、MSC、自动关机／电量、最后接线。每项显示菜单路径，右侧常驻显示相机界面右上角关键项小卡；下方一次声明“以上设置已完成，相机已连接并保持开机”，再连接检查 | `confirm_preparation` 只接受布尔值，在准备阶段且环境、阅读均通过时设置四个稳定准备 ID；不枚举或访问 USB，不能覆盖环境失败或固件兼容性 |
| 功能管理 | 检查成功直接进入，不再弹重复结果确认。功能列表每项同时显示状态、选择和依赖；右侧先选解锁／关闭，再列出实际需修改的功能及数量 | 默认选中未解锁项；状态已符合的不重复写入；空选择、未知字段、守卫不匹配、未满足依赖仍由共用执行器拒绝 |

须知与准备阶段的主按钮固定在底部，滚动长文不会遮住下一步。右上角随时可复看须知，复看不改变会话状态。“返回”回到须知；“重新连接”先结束原会话，清除准备声明及兼容性，再回到准备页，不能直接继续写入。

没有 FTP 菜单是正常情况，不需要去寻找或开启它；如已有且开启，关闭传输后重启释放介质占用。日常 USB 管理只使用普通数据线，Pico 救砖接线属于独立流程。菜单路径与示意来源由 `preparation.py` 提供，图解只保留右上角关键项并标记“非实机截图”。

## 功能管理

功能管理页保留一个功能列表，不在设备卡片和操作面板里重复列状态。选中项和将改变的项区别显示；“选择未解锁”“选择可关闭”“全选／清空”只改变选择，不会连带发起写入。功能级依赖由服务端清单声明；当前开放项之间没有字段依赖，最终判断仍在执行器。

桌面暂时隐藏备份与恢复：没有独立页签、“更多工具”入口或占位按钮，主界面只展示解锁和关闭。待完整备份恢复实现并验证后再设计入口。原有稀疏备份恢复核心、开发者命令、测试及用户备份文件保留；本次不新增完整备份、自动备份或历史撤销。写入前记录和事务保护不变。

## 执行与结果

- 发出操作后立即锁定模式、选择及重复操作；关窗和正常退出仍受繁忙状态保护。
- 进度页优先显示当前阶段和实际经过时间，过程记录折叠展示，不估计百分比或剩余时间。
- 取消按钮只发出一次请求，随后显示“正在等待结果”；不会强制终止已发送写入，也不会自动重发。
- dev34 解锁／关闭成功或无需修改后进入独立结果页，不自动返回功能列表。明确区分“写入与独立回读通过，待机身验收”和“原已是目标状态，未重复写入”；演示结果明确标注不访问真实相机。
- dev36 结果页明确分为六步：“关机 → 断开 USB → 拔出电池 → 等待至少 10 秒 → 插入电池 → 开机检查”；断开 USB 时也断开其他外接供电，不再把这项藏在拔电池的附注中。应用无法知道何时拔下电池，不从进入页面开始自动计时。
- 只展示本次选择功能的菜单路径、解锁／关闭的成功标准及模式条件；已符合目标的项目单独标为未重复写入。固定底栏“继续操作，重新连接”返回准备页，清除旧准备声明和兼容结论；再次确认准备并读取当前状态后才能继续管理功能。
- 物理 unlock／close 在事务、独立回读及记录完成后结束 USB 会话并释放共享锁，才返回结果；如果退出服务未确认，保留写入结果并单独提示，不能把成功回读伪装成退出成功。失败／不确定结果不套用成功指引。
- 失败、内容不兼容、回退及结果不确定分别展示原因和下一步。原始错误、写入尝试标记与过程放入“诊断详情”。不确定结果不包装成成功，也不提供一键重复写入。
- dev35 本地服务意外退出时单独显示中断页，解除已死亡服务的假繁忙状态；重新启动入口只重启本机服务、检查环境并返回须知，不自动接管相机或重放请求。若中断发生在解锁／关闭／恢复期间，提示写入结果待核实。

## 演示与相机模式

页眉始终明确当前模式。演示登记八项合成功能（两项历史禁用、六项可演示），不代表完整实机功能验证；实际相机功能列表由正式清单与当前读取决定。演示场景、断连与重连收进右上角“演示设置”，切换场景会使阅读、准备和兼容状态失效。忙碌期间不能切换模式或场景。

切换到相机模式仅做本机启动检查；真正连接检查才可能请求系统管理员授权、接管接口、认证并上传临时读取程序。因此只读预检不是“相机文件系统完全零写入”。只有所选功能的显式执行按钮才发起对应写入操作。

管理员密码属于 Mac 对临时 USB 接管的授权，不是相机密码；普通 MSC 文件传输不经过同一接管流程。准备页和连接进度说明相机会切换到维护服务，MSC 提示可能消失；仅凭相机回到拍摄／菜单页不能判定连接失效，也不能把进入功能列表当作后续通道永不失效的保证。以应用每次操作的预检、执行及回读结果为准。

## 连接占用与强制接管（dev5）

普通用户不需要安装共享调试台：没有其他进程持锁时直接连接，已有但未被持有的锁文件不会触发错误。锁冲突发生在 USB 认证前，单独展示占用页，不称已访问相机。

仅保留一个“强制接管…”入口，没有通用的“请求释放”协议或按钮。检测到一个可唯一定位的同用户占用进程时，确认框列出名称和 PID，要求用户先检查其他相机软件，确认没有拍摄、传输、固件写入任务，再明确确认接管。接管先发 TERM，仍持锁时重新核对进程身份／启动时间、锁 inode 和已知任务状态，再发 KILL；不按名称批量结束程序，不删除锁文件，不重置 USB，不使用管理员权限结束他人或系统进程。

如果无法唯一定位持锁者、已知工具明确有设备任务、进程或锁已改变、确认超过 120 秒，则拒绝结束进程，重新检查或在原工具中退出。已安装本机调试台时可选用其缓存任务状态；没有调试台或没有协作接口不影响普通用户连接。此能力只覆盖可定位的本机共享锁占用，不保证识别所有第三方软件的 USB 独占。

接管前后记录在本机状态目录的 `connection-takeovers/`；不记录凭据。完成后只显示“连接占用已释放”，旧兼容结论失效，用户重新准备并连接后才读取当前内容。结束的工具不自动重开，接管不自动续写、不改变原生写入范围或身份／前态／回读守卫。

## 共用服务与贡献边界

`preparation.py` 仍维护 `ftp_stopped`、`camera_msc`、`power_awake`、`usb_connection` 四个准备 ID。单次人工声明不会跨启动持久化，CLI 的逐项确认保持不变。每次设备操作继续使用相同设备锁、当前内容预检、写前记录和回读逻辑。

UI 不实现补丁、地址或固件规则。模块入口见 [AI 代码地图](AI-CONTEXT.md)，构建与测试见 [桌面应用说明](DESKTOP-PREVIEW.md)，备份边界见 [功能状态备份与恢复](BACKUP-RESTORE.md)。

## 开机后的检查路径

检查说明统一在 `desktop/aftercare.py` 维护，SwiftUI 只呈现。以下为 A6700 2.00 本项目解锁记录中的菜单路径；语言／拍摄模式会影响显示，不能把其它机型的帮助页当作 A6700 的实机验收。

| 功能 | 菜单路径 | 解锁后检查 | 关闭后检查 |
|---|---|---|---|
| FTP 传输 | 网络 → 传输/远程 → FTP传输功能 | 能进入 FTP功能、服务器设置；需自行配置后才可测试网络传输 | 新增 FTP 入口不再显示 |
| 关机快门帘 | 设置 → 设置选项 → 防尘功能 → 关机时快门 | 出现选项；设为开后正常关机闭帘、开机打开，注意静音联动 | 新增“关机时快门”选项不再显示 |
| 灵活曝光 | 拍摄 → 照相模式 → 曝光控制类型 | 视频模式下可选灵活曝光；曝光/颜色 → 曝光 → 自动/手动切设 中可分别控制 Av、Tv、ISO | 新增灵活曝光入口不再显示 |
| 电子快门声音 | 设置 → 声音选项 → 音频信号 | 出现“开：仅电子快门”“开：除快门以外”；照片模式、关闭静音并选电子快门试听 | 仅保留开／关；必要时触摸选回有效项 |

原厂菜单分组参考 [A6700 帮助指南](https://helpguide.sony.net/ilc/2320/v1/zh-cn/contents/221h_list_of_menu_items_ilc2320.html)，其中不包含本项目所有解锁入口；菜单出现不等于所有拍摄场景均已验收。


FL23（0.3.0）：允许与FTP等功能一起勾选，不自动取消其他选择。同一连接内先执行原四项中的所选功能，再执行FL23，均新鲜读前／独立回读；最后复查原有功能保持。全部通过才显示成功，中途失败显示已确认与未完成范围。0.3.1关闭FL23前先在机身选择ST；关闭会同时恢复其CP代码与参数、启动入口并清理功能包，只撤回该功能的登记修改。
