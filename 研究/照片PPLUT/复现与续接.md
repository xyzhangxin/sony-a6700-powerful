## 从离线代码接续

以下从本目录运行，命令以 PowerShell 为例。使用 Python 3.12、Zig 0.13.0，输入为上表的本地文件。离线测试用 Unicorn 2.1.4。`cp_thumb_fixture_reads.py` 通过指令钩子观察有限的访存，规避该版本 Thumb IT 指令受内存前置钩子影响的情况。输出放在独立临时目录。所有命令只访问本地文件和仿真内存。

```powershell
python -m pip install capstone==5.0.9 unicorn==2.1.4 pyelftools==0.33 numpy==2.5.4 Pillow==12.3.0
$fw = '<固件提取目录的绝对路径>'
$kmod = '<两个 .ko 所在目录的绝对路径>'
$zig = '<Zig 0.13.0 可执行文件的绝对路径>'
$work = Join-Path ([System.IO.Path]::GetTempPath()) ("a6700-pplut-" + [Guid]::NewGuid())
New-Item -ItemType Directory -Path $work
$ap = Join-Path $fw 'files/nflasha15/lib/appFw.so'
$cp = Join-Path $fw 'files/nflasha8/cpapp-b.bin'
$ldr = Join-Path $fw 'files/nflasha8/loader_spi.bin'
$ulog = Join-Path $fw 'files/nflasha15/lib/libosal_ulogio.so'
```

## 实机恢复与研究续接

1. **先建立恢复入口。** 本机九个 CP 写前扇区已保留，机主后来反馈相机已维修恢复，具体维修方法未取得。恢复入口需核验机型、固件、存储范围和加密视图。只有 HID 时，现有 Powerful MSC 维护入口无法写回。Pico 手册的引导能读已知范围。Pico 读到的 eMMC 原始密文与 Linux 维护通道的逻辑视图不能直接互相写回。本案的独立写回和冷启动恢复仍待验证。 [故障记录](实验记录.md#照片记录器冷启动失败) · [Pico 操作手册](../../操作手册.md)
2. **先验证引导和回滚，再加观测。** 保留原早期 CP 引导。用冷启动无 AP 探针的原代码和直连 `0x80` 做对照。在正常启动后优先探索临时观测。CP 运行时写入的取指／数据缓存可见性和回滚条件仍需验证。后续若需要任何跨启动写入，先证明 MSC 不可用时的恢复入口，以及能独立读回的故障阶段、PC／状态或心跳。
3. **先证明一张照片的回执归属。** 保持照片 `mode=0/kind=1` 和默认输出策略，记录一次 AP `0x4155` 与同代 CP User3D 完成。按任务关联四条带、有效持有句柄、最后一条带、晚到回调和主 JPEG 描述符。为普通功能、进程退出和撤回保留独立验收。
4. **再验收图像和菜单。** 用已知归属开启一轮 Main，按诊断 LUT A/B/A 比较全尺寸直出主 JPEG。单独检查照片取景，再接入照片挡原生 PPLUT 菜单选项。FL23／中文沿独立对照查兼容。
